# Changelog

Формат соответствует [Keep a Changelog](https://keepachangelog.com/ru/), версии — [SemVer](https://semver.org/lang/ru/).

## [0.2.0] — 2026-09-13

Ребаза доменной модели по результатам полного аудита и двух частей критики проекта: из CRUD-системы над деревом целей CAOS становится системой коллективного целеполагания над графом целей с проверяемыми результатами. Подробная карта работ — `docs/plan-caos-0.2.md`.

### Security

- Удалены утёкшие в git секреты (Stepik OAuth, FTP-пароль) и секретоносные скрипты; ранбук ротации и чистки истории — `docs/security/secret-cleanup.md`.
- `.gitignore` переписан (вторая половина файла была нечитаемым UTF-16 и не работала).
- Деплой: запускается только после зелёного CI, убран `pytest || true`, секреты передаются через `env:` вместо интерполяции в shell, health-check по `/health`, `DATABASE_URL` читается из `.env`, бэкап перед миграциями.

### Fixed — критичные баги авторизации

- Вход по паролю возвращал 500 всегда (сериализация datetime в `JSONResponse`) — сломано с июля, маскировалось OAuth-входом.
- Неподтверждённый email Google позволял войти в существующий локальный аккаунт (takeover).
- OAuth-вход (Google/Stepik) не создавал серверную сессию — refresh-токен всегда отклонялся.
- `verify_password(None)` падал 500 на OAuth-аккаунтах.
- Один токен без срока годности служил и верификацией email, и сбросом пароля; теперь разные токены с TTL (24ч/1ч), в БД только хеш.
- Logout / смена пароля / сброс / удаление аккаунта не отзывали серверные сессии — теперь отзывают.
- Перечисление пользователей при регистрации; падение регистрации при ошибке SMTP; гонка одновременной регистрации.

### Fixed — доменные дефекты («10 дефектов» критики)

- Назначение задачи только участникам проекта; голосование только участникам контекста цели; проверка доступа (не только существования) при связывании Goal/Project/Decision с чужими объектами; честный `decision_method` (majority/unanimity/supermajority/consent вместо «консенсуса» простым большинством); AI-ретривал ограничен правами пользователя; публичный профиль без чужого email; агрегаты голосов вместо списка голосующих до финализации.
- Поиск на PostgreSQL падал 500 (несуществующий оператор `+` для конкатенации в `to_tsvector`).

### Added — доменная модель 0.2

- **Граф целей**: `goal_relations` — типизированные рёбра (concretizes/depends_on/supports/conflicts_with/contributes_to/blocks/supersedes) с обоснованием, защитой от запрещённых циклов и `GET /goals/{id}/impact` (что остановится, если цель провалится).
- **Жизненный цикл цели**: 12 серверных переходов `draft → … → closed`; произвольная смена статуса невозможна; перевод в `achieved` требует верифицированного результата (INV-3).
- **Коллективное признание** (D1): цель с активными участниками принимается только через принятое коллективное Decision (`RECOGNITION_REQUIRED`); матрица прав `permissions.py` — capabilities по контекстным ролям вместо owner-only власти.
- **Участие**: `goal_participations` — контекстные роли, join/leave с историей; участие само по себе даёт доступ к цели.
- **Обязательства**: `commitments` — добровольные обязательства с машиной состояний; задачи связываются с целями через них (`tasks.commitment_id`).
- **Измеримость и результаты** (C5): `goal_criteria` (baseline/target/unit/weight) + `goal_measurements`; `results → evidence → verifications` — автор результата не может верифицировать его сам (INV-4).
- **Решение как процесс** (C6): типизированные события (argument/objection/alternative/revision/…), неизменяемые `proposal_versions`, срок жизни решения (`valid_until`/`review_at`), `challenges` — возражение как объект с обязательным ответом.
- **Связности** (C7): `project_goals` M2M (проект служит нескольким целям), `knowledge_relations` (знание поддерживает цели/решения/результаты).
- **AI-предложения** (G1): каждый ответ AI сохраняется с моделью, снимком входа и confidence; резолюция фиксирует ревьюера. Ранее предложения AI не создавались вовсе.
- **Контракт ошибок** (E2): машиночитаемые коды поверх `detail` (`INVALID_STATE_TRANSITION`, `SELF_VERIFICATION_FORBIDDEN`, `FORBIDDEN_SCOPE`, …).
- **Alembic** (7 миграций): конвергентный baseline, закрывший дрейф схемы после `create_all`; миграции в CI и деплое.

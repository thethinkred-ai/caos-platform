---

Ребаза доменной модели по полному аудиту проекта: из CRUD-системы над
деревом целей CAOS становится системой коллективного целеполагания над
**графом целей** с проверяемыми результатами.

### Граф и жизненный цикл целей
- Типизированные рёбра `goal_relations`: concretizes / depends_on / supports / conflicts_with / contributes_to / blocks / supersedes — с обоснованием и защитой от запрещённых циклов
- `GET /goals/{id}/impact` — что остановится, если цель провалится
- Жизненный цикл `draft → proposed → accepted → active → achieved → verified → closed` — только серверными командами; произвольная смена статуса невозможна

### Люди вокруг целей, а не структур
- Участие с контекстными ролями (contributor / coordinator / expert / facilitator / observer)
- Добровольные обязательства (commitments) связывают задачи с целями
- Матрица прав: capabilities по роли в цели; цель с участниками принимается **только коллективным решением** (`RECOGNITION_REQUIRED`)

### Выполнено ≠ достигнуто
- Измеримые критерии целей (baseline / target / unit) и динамика измерений
- `Result → Evidence → Verification`: автор результата не может верифицировать его сам
- Перевод цели в `achieved` физически требует верифицированного результата

### Решение как процесс, возражение как объект
- 4 честных метода (majority / supermajority / unanimity / consent), версии предложений, срок жизни решения
- `Challenge` для целей/решений/результатов с обязательным записанным ответом

### AI предлагает — люди решают
- Каждый ответ AI сохраняется как предложение (модель, снимок входа, confidence) и меняет домен только после человеческого ревью

### Безопасность и фундамент
- Закрыты критичные баги авторизации (в т.ч. сломанный с июля вход по паролю и takeover через неподтверждённый email Google)
- Секретоносные скрипты удалены, деплой только после зелёного CI, бэкап перед миграциями
- Alembic (7 миграций), машиночитаемые коды ошибок, тесты: 23 красных → **102 зелёных**
